# 软件计划文档

## 1. 系统概述

EmoAgent 是一个面向文本情绪分析场景的智能 Agent 系统，主要用于对用户聊天、评论、客服对话等文本进行情绪识别、反讽识别、混合情绪识别，并输出结构化分析结果。系统采用“前端页面 + Spring Boot 后端 + Python FastAPI Agent 服务”的分层架构：前端提供登录、聊天工作台、历史情绪变化和实时洞察展示；后端负责统一接口、认证授权、数据持久化与 Agent 编排；Agent 服务负责调用大模型并完成 router、emotion、sarcasm、mix、judge 等分析链路。

系统主要用户包括普通运营人员、客服质检人员、内容审核人员和管理员。系统边界限定为文本输入情绪分析，不处理语音、图片、视频等多模态内容；数据保存、权限控制、调用日志、统计展示等能力由后端和前端协同完成。

## 2. 软件开发过程模型

本项目采用原型迭代与敏捷开发相结合的过程模型。情绪分析 Agent 的识别效果、前端交互体验和后端接口契约都需要在实现过程中不断验证，因此先完成可运行原型，再围绕核心功能、用户体验、测试与部署进行短周期迭代。

| 软件生命周期 | 是否首先定义好所有需求 | 是否有多个开发周期 | 是否有中间软件 |
|---|---|---|---|
| 原型迭代 / 敏捷开发 | 否，先定义核心需求并持续细化 | 是 | 是，可运行的前后端与 Agent 原型 |

## 7. 风险估计和控制

| 风险描述 | 降低风险策略 |
|---|---|
| 大模型接口不稳定、超时或返回格式不符合预期 | 增加超时控制、结果校验、降级输出和错误日志；关键字段使用结构化 schema 校验 |
| 反讽和混合情绪识别准确率不足 | 建立典型样例集，持续补充测试用例，按 Router、Sarcasm、Mix 分模块评估 |
| 前后端与 Agent 接口契约变更导致联调阻塞 | 维护统一 DTO / schema 文档，接口变更先评审后实现 |
| 用户文本涉及隐私或敏感信息 | 增加权限控制、日志脱敏策略和最小化存储原则 |
| 并发量升高导致响应时间不达标 | 引入缓存、限流、异步处理和服务监控，必要时横向扩展 Agent 服务 |
