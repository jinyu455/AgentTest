1. base_client.py:将原始llm返回字符串解析为json格式，方便后续解析
2. coerce.py：删除json空格和空字符串，提供了所有类型转换方法，能将json数值进行转换
3. llm_config.py:api配置
4. schemas.py:定义情绪字段，输入字段的数据结构

3. schemas.py:定义emotion输出字段数据结构，将json转化为字典

### 六、judge_agent

1. client.py:同
2. llm_agent.py：

- 大模型复核规则：
  - sarcasm_confidence_threshold，mix_confidence_threshold超过0.65才认为该情绪成立,小于时复核
  - emotion_confidence_threshold<0.65大模型复核
  - review_confidence_margin，即两个agent(emotion和其他)置信度差小于这个0.15会调用大模型复核，原因是两个agent置信度差距不大时，无法判断谁更可信，必须复核
- sarcasm识别的true_emotion与emotion不同
  - mix识别的primary_emotion与emotion不同
- rule_result构造：
  - direct:直接采纳emotion_agent结果
  - sarcasm:进入_judge_sarcasm_branch（进入这里都会是need_sarcasm_check=true,但是最后is_sarcasm不确定）
    - is_sarcasm&&反讽置信度>=0.65，sarcasm成立，将true_emotion(revised_emotion)作为final_emotion，置信度按 3:7 加权（情感 30% + 反讽 70%），强度为revised_intensity
    - is_sarcasm&&反讽置信度<0.65,sarcasm成立但是置信度不足，将emotion_agent的情绪作为final_emotion,置信度*0.8，强度为emotion_intensity
    - !is_sarcasm，将emotion_agent的情绪作为final_emotion,置信度*0.9，强度为emotion_intensity
  - mix：进入_judge_mix_branch(进入这里都会是need_mix_check=true,但是最后is_mix不确定)
    - is_mixed&&mixed置信度>=0.65,mixed成立，采纳mix_agent的primary_emotion作为final_emotion,secondary_emotion，置信度按 3:7 加权（情感 30% + mix70%），强度为adjusted_intensity
    - 同sarcasm
- rule_result和llm的关系：不需要llm复核时，rule_result即可，需要介入时，将rule_result作为上下文发给llm（rule_result是一个快速但不准确的预判）

### 八、chat_agent

1. client.py:temperature=0.4高一点，让llm回答更多样
2. llm_agent.py:先构造合法的回复语气和风险提示标签集合，定义提示词，让llm根据最近对话历史回答用户，在possible_crisis时，tone选择crisis_support。输入是judge_result(judge_agent的结果) history metadata,history为近20条user 和 assistant 角色的对话信息,根据role分类的content，只接受user、assistant
3. schemas.py:定义chat_input chat_result字段数据结构

### 九、profile_agent

1. client.py:生成用户画像，包含字段
   - personality_traits:基于情绪模式推断的 2-4 个核心性格特征,"内向敏感", "追求完美", "情绪化"
   - communication_style:用户在对话中的沟通倾向,"偏好简洁回应，情绪低落时会用反讽表达"
   - emotional_patterns:情绪变化规律和触发因素,"工作压力大时容易焦虑，周末情绪较稳定"
   - mbti:根据用户对话判断mbti类型
   - summary,整体画像总结,"情绪波动较大，反讽率高，需关注压力管理"
2. feature_extractor.py:不需要llm纯计算
   - intensity_trend:利用最小二乘法拟合强度分布斜率，abs>0.5:判断上升和下降，否则为平稳
   - extract_features:
     - total_records:总统计条数
     - emotion_distribution:各种情绪分布比例
     - avg_intensity,avg_confidence:强度置信度均值
     - sarcasm_rate,mixed_rate:反讽、混合情绪比例
     - dominant_emotion：出现最多的情绪
     - activity_pattern:按照时间段桶统计用户活跃时间
3. llm_agent.py:
   - 让llm根据用户历史情绪统计数据和对话摘要生成用户画像的prompt,少于10条记录时summary指出数据量不足生成仅供参考。
   - 摘要为根据role分类的content，只接受user、assistant
   - 提供了两个不同的接口：
     - profile()：调用extract_features(),不需要llm，仅生成统计数据
     - generate():生成完整的用户画像，根据统计数据和用户摘要，生成用户画像字段
4. visualzer.py:
   - 生成情绪分布雷达图 情绪时间线  强度直方图
5. schemas.py：定义EmotionRecord 用户画像生成的输入参数ProfileInput，用户画像结果ProfileResult

### 十一、utils.py

1. 路由模块降级 `_fallback_router`

- **触发场景**：Router LLM 调用失败
- 降级策略
  1. 路由类型强制设为 `direct`（直接执行，不做复杂路由）
  2. 关闭反讽检测、混合情绪检测
  3. 标记降级状态与失败原因
- **返回结果**：固定基础路由信息 + 降级说明

---

2. 情绪识别模块降级 `_fallback_emotion`

- **触发场景**：Emotion LLM 调用失败
- 降级策略
  1. 情绪默认设为 **中性**
  2. 强度默认设为 **30**
  3. 置信度设为低可信度 **0.2**
  4. 各类情绪关键词列表清空（无词汇）
  5. 标记降级状态与失败原因
- **返回结果**：合法中性情绪结构，保证流程可继续

---

3. 反讽检测模块降级 `_fallback_sarcasm`

- **触发场景**：Sarcasm LLM 调用失败
- 降级策略
  1. 直接判定 **无反讽（is_sarcasm=False）**
  2. 表面情绪 & 真实情绪均设为 **中性**
  3. 强度默认 30，置信度 0.2
  4. 标记降级状态与失败原因
- **返回结果**：安全无反讽默认值

---

4. 混合情绪模块降级 `_fallback_mix`

- **触发场景**：Mix LLM 调用失败
- 降级策略
  1. 直接判定 **非混合情绪（is_mixed=False）**
  2. 主情绪设为 **中性**，无次要情绪
  3. 强度默认 30，置信度 0.2
  4. 标记降级状态与失败原因
- **返回结果**：单一中性情绪结构

---

5. 最终裁决模块降级 `_fallback_judge`

- **触发场景**：Judge LLM 调用失败
- 降级策略（双层兜底）

  1. **优先尝试**：使用规则版 JudgeAgent 做裁决
  2. 规则也失败

     ：直接使用

     情绪识别结果兜底

     - 最终情绪 = 中性 / 已有情绪结果
     - 最终强度 = 30 / 已有强度
     - 置信度 = 0.2
     - 无反讽、无混合情绪
  3. 统一标记降级状态
- **返回结果**：可用的最终裁决结果，保证输出完整

---

6. 用户画像模块降级 `_fallback_profile`

- **触发场景**：Profile LLM 调用失败
- 降级策略

  1. 保留可用统计数据

     （不依赖 LLM 的部分）

     - 总记录数、情绪分布、平均强度、活跃时段等
  2. LLM 生成字段清空 / 降级

     - 性格特征为空列表
     - 沟通风格、情绪规律、总结字段标记 “LLM 调用失败”
  3. 可视化图表数据正常生成
  4. 标记降级状态与失败原因
- **返回结果**：可用统计画像 + 提示 LLM 部分不可用
